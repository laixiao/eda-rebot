======= 环境 =======
& 'C:\Espressif\tools\Microsoft.v5.5.5.PowerShell_profile.ps1'


======= 构建 =======
主系统：
  cd firmware
  idf.py build
  → firmware\build\eda_robot.bin（开 SPIRAM 时约 5MB+，含语音模型；语音运行时默认不启动）

救援：
  cd firmware_recovery
  idf.py build
  → firmware_recovery\build\eda_rescue.bin

大包只烧 ota_0（0x120000 / 救援 OTA），不要烧 factory（1MB）。

（build 被占用打不开时，可临时：idf.py -B "$env:TEMP\eda_robot_build" build）


======= 产物路径（项目内）=======
主系统：firmware/build/eda_robot.bin
救援：  firmware_recovery/build/eda_rescue.bin

======= 全量刷（首次 / 改分区 / 救砖）=======
在仓库根目录执行（COM 口按实际改）：

  .\scripts\flash_all.ps1 -Port COM4

会编译并写入 bootloader / 分区表 / otadata / 救援 / 主系统。
不要用 idf.py flash（地址不对）。

只刷主系统：
  python -m esptool --chip esp32s3 -p COM4 -b 460800 write_flash 0x120000 firmware\build\eda_robot.bin

说明：供电不稳也能刷；跑大包时若 BROWNOUT 需加稳 5V。语音默认关（网页「语音」开关 / POST /api/voice），不开就不 init AFE。

======= 监视 =======
cd firmware
idf.py -p COM4 monitor --no-reset

======= 日常 OTA（大包 → ota_0）=======
主系统不能直接刷自己（单槽），必须先救援再上传。

网页：主页「进入救援升级」→ 看 IP → 上传 eda_robot.bin

API（PowerShell 示例，IP 按实际改）：
  # 1) 主系统：进救援（会重启）
  Invoke-RestMethod -Method POST -Uri http://192.168.137.178/api/rescue

  # 2) 等 OLED 显示救援 IP 后，上传大包（原始 bin，非 multipart）
  Invoke-WebRequest -Method POST -Uri http://<救援IP>/api/ota `
    -InFile firmware\build\eda_robot.bin -ContentType "application/octet-stream"

  # 成功返回 {"ok":true,"reboot":true} 后自动回主系统

curl 等价：
  curl -X POST http://192.168.137.178/api/rescue
  curl -X POST http://<救援IP>/api/ota --data-binary @firmware/build/eda_robot.bin

语音开关（大包刷上后，默认关）：
  Invoke-RestMethod -Method POST -Uri http://<主IP>/api/voice -ContentType application/json -Body '{"on":true}'
  Invoke-RestMethod -Method POST -Uri http://<主IP>/api/voice -ContentType application/json -Body '{"on":false}'
